## 2. ⚠️ 改动作维度时最容易踩的三个陷阱

### 陷阱一：`_FakeSpacesOnlyEnv` 的 `joints` 参数一参两用

`config.py` 给 learner 用的空壳，**同一个 `joints` 同时喂给 `state_dim` 和
`action_space`**：

```python
state_dim = joints * len(proprio_keys)          # 6 × 2 = 12
self.action_space = Box(-1, 1, (joints,))       # 6
```

照字面把 `joints=6` 改成 3，会让**观测维度从 12 变成 6** —— 而且是静默错，
到 `ReplayBuffer` 形状不匹配时才炸，很难查。

**已拆成两个参数**：`n_joints`（观测里的关节数，= `N_ALL` = 6）与
`n_action`（动作维度，= `N_ACTION` = 3）。实测 learner 侧：

```
observation['state'].shape = (12,)     ← 没被误改
action_space.shape         = (3,)
```

### 陷阱二：夹爪不在动作里 ⇒ `setup_mode` 必须换

HIL-SERL 的 `SACAgentHybridSingleArm`（`setup_mode='single-arm-learned-gripper'`）
会把**最后一维**当成夹爪离散头：

```python
action_dim = actions.shape[-1] - 1
```

我们的最后一维是 `wrist_flex`。若不换 setup_mode，**wrist_flex 会被当成夹爪**，
动作语义整个错位，而且不一定报错。

**已改成 `setup_mode = 'single-arm-fixed-gripper'`** → 走普通 `SACAgent`，
3 维全连续（`action_dim` 由 `env.action_space.sample()` 的长度决定）。

### 陷阱三：`env.py` 里 import 同目录模块，训练路径会找不到

`env.py` 需要 `from so101_home_pose import ...`，但真实训练路径是
`import experiments.so101.env` —— 此时 `sys.path` 上只有 `examples/` 和
`experiments/`，**不含 `so101/`**，所以顶层模块名 import 会
`ModuleNotFoundError`。

**已在 `env.py` 里把自身目录插进 `sys.path`**（不是用相对 import，
这样 `env.py` 被当脚本直接跑时也能用）。实测：`TrainConfig().get_environment(
fake_env=True)` 可以正常 import。

## 3. ⚠️（历史）冻结 `shoulder_pan` 的运动学后果

> **2026-09-29 起 pan 已解冻，本节描述的"末端被锁在一个竖直平面内"的限制
> 不再成立。** 保留此节是因为它是理解 §3.6/§3.7 的背景，也记录了一次真实的
> 权衡过程。当前的随机化是**只转 pan 的水平弧**（§3.8）。

`shoulder_pan` 是唯一能绕**竖直轴**转的关节。把它冻结，末端就被锁死在
**一个竖直平面**内。实测（起点附近随机采样 4000 个位形，对末端位置做 SVD）：

| 冻结 | s1 | s2 | s3 |
|---|---|---|---|
| 只冻 `wrist_roll` | 0.1242 | 0.0984 | 0.0382 |
| **冻 `wrist_roll` + `shoulder_pan`** | 0.1242 | 0.0372 | **0.0000** |

`s3 / s1 = 1.5e-15` —— 最小奇异值为 0，点云**严格二维**。

- 平面是**竖直**的（法向 `[+0.325, +0.946, 0.000]`，无 Z 分量）
- 平面内可动方向：竖直（±Z）+ **一个**水平方向 ≈ `[0.946, −0.325, 0]`
  （基座系里偏离 +X 轴约 −19°）

### 对起始位置随机化的影响 —— **已作废**（当时曾决策并实现）

末端不能做二维水平平移，所以水平面内的 5cm × 5cm 方形随机化**做不到**。

> **2026-09-29 用户决定**：接受这个限制，保持 `pan` 冻结，随机化按
> "沿 `[0.946, −0.325, 0]` 一个方向 + 竖直方向"来做。
>
> **同一批"2 个方向"的限制在 pan 解冻后还存在过一段时间**，表现为
> "三维框 + IK"；现在的方案见 §3.8。

**当时实现**在 `env.py::reset()` 与 `so101_home_pose.randomize_start_pose()`：
在竖直平面内采 ±2.5cm，用 IK 解出受控关节（`locked_idx` 锁死 pan / wrist_roll），
再按 `_publish_arm_ramp` 平滑走过去。

离线整框验证（`phase0_randomize_check.py` 老版本）：**441/441 网格点 + 2000/2000 随机采样全通过**，
位置残差 ≤1mm、管子倾角变化 ≤0.045°、限位余量 ≥1.07rad、锁定关节漂移恒为 0。

> ⚠️ 这批数字**至今仍然是真的** —— 但它们只覆盖末端位置和倾角，
> **没有覆盖关节空间姿态**，所以后来"起点有时非常高"（§3.8）就是从这儿漏过去的。

## 3.5 ⚠️ 起始姿态：重力静差补偿（不做会让管子歪 8.75°）

这是本次最容易漏掉、后果最严重的一条。

### 3.5.1 现象

舵机是**比例位置环且 `I_Coefficient = 0`**，顶住重力必须存在
`误差 = 重力力矩 / Kp` 的稳态静差。所以**发"名义角"，手臂停在名义角下方**。
实测（从臂夹着试管）：

| | 末端 z | 管子距竖直 |
|---|---|---|
| 名义起点（Phase 0 验证过） | 16.05cm | **1.661°** |
| 直接发名义角后的实际平衡点 | 12.40cm | **8.754°** |

管子歪 8.75° 是不能接受的 —— 插管必须基本竖直，Phase 0 的验证也就白做了。

### 3.5.2 做法：归位脚本把收敛指令存档，`reset()` 复用

`phase1_home.py` 的迭代修正本质上就是在求"要多推多少"（`cmd − 目标`）。
归位成功后，它把这个偏置写进存档：

```
hil-serl/examples/experiments/so101/so101_home_cmd.json
{ "target": [...], "follower_cmd": [...], "follower_offset": [...] }
```

`env.reset()` 读它做补偿：**先跑一次归位脚本，才能开始训练。**

一次实测的偏置：`shoulder_lift −2.55°, elbow_flex −4.22°, wrist_flex −0.88°`
（与关节灵敏度、以及归位脚本的迭代量都对得上）。补偿后管子倾角回到 **1.83°~2.26°**。

### 3.5.3 ⚠️ 固定补偿还不够，必须加"实测反馈"

那个偏置是在**名义点**上标定的。换到随机点后重力力矩变了、静摩擦死区也变了，
实测**偏高 1~2cm**：

```
请求竖直 +2.44cm  →  实际 +4.42cm     ❌（只加固定补偿）
```

所以 `reset()` 里又加了一轮**实测反馈**（与归位脚本的迭代修正同一个思路）：
量出 `目标 − 实测`、补进指令、再走一小段。修复前后：

| | 请求→实际位置偏差 | 管子倾角 |
|---|---|---|
| 只用固定补偿 | 均值 13.2mm / 最大 20.1mm | 0.54°~2.43° |
| **加一轮实测反馈** | **均值 2.16mm / 最大 4.06mm** | **1.83°~2.26°** |

### 3.5.4 为什么归位要用**多点 min-jerk 轨迹**而不是单点

`so101_controllers.yaml` 里的 `arm_controller` **没有配任何 velocity /
acceleration 约束**，所以 `time_from_start = 3ms` 的单点轨迹就等于"立刻到位"
—— 从臂会**突然弹过去**，而夹爪里还夹着试管。

`env._publish_arm_ramp()` 改用一条 26 点的 min-jerk 轨迹（首末速度/加速度为 0），
时长按峰值速度反推（峰值 = 1.875 × 位移 / 时长）。JTC 自己会插值，我们只睡够时长。

### 3.5.5 `reset()` 也不再发夹爪指令

原代码 `reset()` 里有 `_send_gripper(-1.0)`，而 `GRIPPER_CLOSE_RAD = −0.2 rad`，
会把夹爪从保存的 **+0.325 rad 压过去 0.5 rad** —— 每个 episode 都挤一次试管。
夹爪既然冻结，就一个指令都不该发（位置由 ros2_control 的夹爪控制器保持）。


## 3.6 🔴 真机踩到的两个坑（2026-09-29，首轮录制后）

两个都由**冻结关节 + 比例位置环**这对组合引起，且都会静默劣化数据。

### 坑一：目标点算在"名义平面"里，而 `shoulder_pan` 锁在实测值 → IK 必失败

`randomize_start_pose()` 原来用 `START_JOINT_POSE` 算平面法向，但 IK 把 `pan`
**锁死在参考姿态的值**上。平面**只由 pan 决定**，两者一差，目标点就跑到可达平面之外，
位置残差永远消不掉。实测（200 次/档）：

| pan 偏差 | IK 失败率 | 位置残差 |
|---|---|---|
| 0° | 0/200 | 2mm |
| **2°** | **200/200** | 14mm |
| 10° | 200/200 | 70mm |
| 15° | 200/200 | ~105mm ← 真机日志里的 88mm / 102mm 就是这个 |

**修法**：参考姿态 = 名义姿态，但**冻结关节取实测值**；平面、原点、姿态参考
全部按它算。这样目标点**按构造就在可达平面内** —— 复验：pan 偏 35° 也是
**200/200 通过、残差 ≤2mm**。

### 坑二：`pan` 被推动后，整个任务几何就错了 —— 而且**起点姿态本身包含 pan**

`pan` 是"冻结"的（控制回路里谁也不许动它），但**起点姿态的定义里它就是名义值**。
真机上它偏了约 13~15°（多半被手碰过或回程带偏），于是：

- 可达平面被转过 → 管子够不到固定的孔
- 而 `reset()` 原来把 pan **锁在实测值**，等于把这个错误"固化"成新的起点

**修法**：
- `reset()` 的起点姿态**包含 pan 的名义值**（`_publish_arm_ramp(..., hold_idx=(4,))`
  只锁 `wrist_roll` —— 它锁实测是因为管子轴对称、值无意义）
- 实测 `pan` 偏差 > 2° 时**告警**，说明平面被转过、本次会拉回

### 坑三：模式 A 的指令 = 实测位置 → **没有顶重力的力** → 从臂缓慢下垂

舵机是比例位置环，`指令 = 实测位置` 意味着**比例误差恒为 0** → 没有任何力顶重力
→ 手臂一路缓慢下垂。而接管瞬间模式 B 的指令是**冻结住的**
`foll_anchor + home_offset`，比已经垂下去的位置高 → 从臂"弹回去一下"。

这正是用户报的"**复位不如归位脚本准**"和"**接管时从臂会变一下**"，两个现象同一个根因。

**修法**（就是用户提的"把固定时候的那个作为一个残差项"）：**两个模式都加**同一个
重力静差补偿 `home_offset`：

```
模式 A: target = cur + action × scale + home_offset
模式 B: target = foll_anchor + (leader − lead_anchor) + home_offset
```

- 模式 A 不再漂浮
- 接管瞬间两式**恒等**（`foll_anchor == cur`、`leader == lead_anchor` 在同一刻取值）
  → **零跳变**（已验证：5 组随机位形下差值 = 0.00e+00°）
- 动作语义不变：仍是"相对实测位置的增量"，`home_offset` 只是植物的一部分，
  录制/训练两侧一致

> ⚠️ "下垂消失"这一条**只能在真机上验证**；公式只能证明接管瞬间连续。

### 顺带：`reset()` 现在会报最终残差

`phase1_home.py` 一直打印 `follower 最终误差 = 0.35°`，而 `reset()` 之前没有这个数字，
于是"复位准不准"只能靠感觉。现在 `info['start']['resid_deg']` 会给出
`|目标 − 实测|`（只算受控关节），录制脚本每段都打出来。

## 3.7 ✅ 解冻 `shoulder_pan`（2026-09-29，历史关节动作方案）

用户要求"操作的时候第一个维度的动作也可以改变"。于是 `shoulder_pan` 从冻结集合
移入受控集合，**动作维度 3 → 4**。

### 为什么这次改变是必要的（不只是"想要"）

锁 pan 时 `shoulder_pan` 只能停在归位时的值。而真机上它**被推动过约 13~15°**，
于是整个可达平面被转过、管子够不到固定的孔 —— 日志里表现为 IK 位置残差 88mm/102mm。
解冻后 pan 成为唯一的侧向自由度，这个失效模式**从根上消失**。

### IK 从"恰好适定"变成"超定"，但实测没问题

4 个关节 / 5 个约束（位置 3 + 管子方向 2）看着超定，但管子方向里那个"离面分量"
实际上是常量、永远自动满足，所以有效约束就是 4 个。实测：

| 项 | 结果 |
|---|---|
| 27 个极端点（角/棱/面/中心） | **全部通过** |
| 2000 次真实 `randomize_start_pose` | **2000/2000** |
| 最差位置残差 | **1.93mm** |
| 最差管子倾角变化 | **0.05°** |
| 最小限位余量 | 1.047 rad |
| 单次耗时 | 3.06 ms |
| pan 偏 35° 时 | 仍然 300/300 |

### 附带的好处：随机化回到真正的三维框

> ⚠️ **已被 §3.8 取代**。三维框正是"起点有时非常高"的来源（IK 零空间），
> 现在改成只转 pan 的水平弧。保留这段是为了说明：当时的验证结论
> "27 个极端点 + 2000 次采样全过"是**真的**，只是它没查姿态。

原来锁 pan 只能在一个竖直平面里做 2 方向（用户当时接受了这个限制）。
现在 `x / y / z` 各 ±2.5cm，是**真正的 5cm 立方**，三轴都均匀
（实测 std 1.431~1.459 vs 理论 1.443）。

### ⚠️ 代价：动作维度变了，旧的 3 维 demo 全部作废

`build_demos.py` 的 space 校验会**明确拦下**它们：

```
ep_0000.pkl: 形状/格式校验失败：step0: actions shape (3,) != (4,)
```

必须**重新录制**。这正是那道校验存在的意义 —— 在训练之前而不是训练之中发现。

## 3.8 ✅ 起始随机化改成"只转 pan"（2026-09-30，当前方案）

### 现象：初始化后手臂**有时非常靠上**

用户报："有时候初始化，从臂会非常靠上，能不能让初始化的随机性小一点，
比如只有第一个维度有比较小的随机性，相当于只水平移动。"

### 根因：IK 的 1 维零空间，而旧验证**只查了末端、没查姿态**

老的随机化是"三维框 + IK"（§3.7）。pan 解冻后有 4 个关节去满足 4 个有效约束，
看似适定，但**零空间并没有消失** —— "pan 转一点 + 手臂反绕回来"能到达**同一个末端
位置和同一个管子方向**。IK 的零空间正则只能让它别乱跳，不能保证解在姿态上接近名义点。

实测 2000 次采样，三个关节的跨度：

| 关节 | 跨度 |
|---|---|
| `shoulder_lift` | **36.2°** |
| `elbow_flex` | **52.6°** |
| `wrist_flex` | **31.5°** |

而同一批采样的末端位置误差 ≤2.5cm（本来就该在框里）、管子倾角变化 0.05° —— 
**全都"正常"**。旧验证（`phase0_randomize_check.py` 老版本）查的正是这两项，
所以它一路绿灯。姿态这一维没人看，手臂偶尔缩到很高就漏了过去。

> **教训（比这个 bug 本身重要）**：验证一个随机化好不好，必须同时看
> **末端**（位置、朝向）**和关节空间姿态**，还要单独确认"锁住的关节真的没动"。
> 只查末端，等于默认"末端对了姿态就对了" —— 对冗余机械臂这从来不成立。

### 做法：不动 IK，只转 `shoulder_pan`

`randomize_start_pose` 重写为**纯关节空间**：只给 `q[0]` 加一个角度，其余关节**一位不动**。

```
末端到 pan 轴的垂直距离 R   （不是 hypot(x, y)！见下）
d_want  = uniform(-1cm, +1cm)           # 请求的末端水平位移
d_pan   = 2·asin(d_want / (2R))         # 弦长 d 对应的圆心角
q[0]   += d_pan
```

由此三件事**精确成立**（离线 3000 次采样实测）：

| 项 | 实测 |
|---|---|
| 末端高度变化 `dz` | ≤ **25 nm**（来自 pan 轴 0.0002° 的装配倾斜，1cm 弦长 × sin(0.0002°) ≈ 35nm） |
| 管子倾角变化 | ≤ **4 µdeg**（浮点噪声） |
| 非 pan 关节跨度 | **严格 0.00e+00°**（根本没有 IK 分支可言） |
| 水平位移 | 0 … 0.9996 cm（请求上限 ±1.0cm，1:1 命中） |
| pan 角度范围 | −1.526° … +1.525° |
| 单次耗时 | 1.20 ms |

代价：随机化沿一条**水平圆弧（切向一个方向）**，不再是三维框 —— 正是用户要的
"相当于只水平移动"。

### 🔴 附带挖出的第二个 bug：pan 轴**不过基座原点**

第一版实现用 `r_h = hypot(p[0], p[1])` 当作"末端到竖直轴的距离"（= 0.412288），
但 FK 给出的 pan 轴实际过的是 **`(x=+0.0388, y=0)`**：

| 量 | 值 |
|---|---|
| pan 轴方向 | `[-0.000000, +0.000003, -1.000000]`（与竖直差 **0.0002°**） |
| pan 轴原点 | `[+0.03884, -0.00000, +0.06240]` |
| 末端到轴的**垂直**距离 `R` | **0.375381** |
| `hypot(x, y)` | 0.412288（**大 1.098 倍**） |

于是弦长被多算 1.098 倍 ⇒ 实际位移只有请求值的 **0.9105 倍**。表现是
"3000 次抽样最大位移只有 0.910cm"，我一开始还以为是"抽样没抽到边界"。

**修法**：不再手算轴位置，而是让 FK 在名义点 ±1e-3 rad 处量一次弦长反解半径
（`R = |p(+ε) − p(−ε)| / (2 sin ε)`）。轴倾角、轴偏置、换 URDF 都不用改这里。

> **教训**：随机化的验证不能只查"落没落在范围内" —— 0.910cm 稳稳落在 ±1cm 里，
> 边界检查**必然通过**。必须拿**请求值**和**实际值**做 1:1 对账
> （`phase0_randomize_check.py` 现在专门有一步做这件事，误差要求 <1µm）。

### 参数与开关

| 位置 | 值 | 说明 |
|---|---|---|
| `so101_home_pose.RANDOMIZE_HALF_M` | `0.01` | ±1cm 水平弧 |
| `config.py:RANDOMIZE_HALF_M` | `0.01` | 必须与上面一致（`env.py` 的默认值取前者，`config` 会覆盖它） |
| `config.py:RANDOMIZE_START` | `True` | 关掉则固定名义起点 |

离线复核：`python phase0_randomize_check.py --n-random 3000`（应全 PASS）。
真机复核：`python test_env_reset.py --n 6`。

## 4. 冻结的唯一正确实现方式

### 4.1 用"实测值"，不要用"固定目标角"

```python
q_cmd = hold_frozen(q_cmd, q_cur)     # 冻结维度 ← 实测值
```

把冻结维度的指令替换成**当前实测值**，也就是"根本不命令它"。

**绝不要写成一个固定的目标角**（例如"pan 恒等于 0.3309"）：归位残差、机械松弛、
被人手碰过，都会在下一刻变成指令里的**一次跳变**。用实测值意味着零回复力 ——
机械臂停在哪儿就是哪儿，永远不会跳。

### 4.2 唯一真相源

只在 `hil-serl/examples/experiments/so101/so101_home_pose.py` 定义：

```python
FROZEN_JOINTS     = ('shoulder_pan', 'wrist_roll', 'gripper')
FROZEN_IDX        = (0, 4, 5)                                   # 0 基
CONTROLLED_IDX    = (1, 2, 3)
CONTROLLED_JOINTS = ('shoulder_lift', 'elbow_flex', 'wrist_flex')
N_ACTION          = 3          # = len(CONTROLLED_IDX)

hold_frozen(q_cmd, q_cur)             # 位置式：冻结维度 ← 实测值
action_to_joint_delta(a3, scale)      # 3 维动作 → 5 关节增量（冻结维恒 0）
joint_delta_to_action(d5, scale)      # 上面那个的逆
```

`action_to_joint_delta` 在维数不符时**直接抛 ValueError**，不静默截断 ——
动作维数错位属于"跑起来不报错、但学出来是坏的"那类问题，必须当场炸掉。

**改冻结维度只改这一个地方。**
