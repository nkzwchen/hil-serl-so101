## 4. 数据流水线（录制 → 训练）

```
record_demo_so101.py   label_demos.py        build_demos.py        push_demos.py
  四阶段状态机     →    人工标成功帧     →   稀疏奖励+校验    →   构建+scp+给命令
  recordings/ep_XXXX.pkl  .labels.json        demo_data/*.pkl      云端 demo_data/
```

### 录制按键（**用户已确认就是这套，不要改**）

| 阶段 | 含义 | 按键 |
|---|---|---|
| `PRECISE` | 自动回随机起点 + 主臂对齐（全自动） | — |
| `READY` | 等你就位 | `c` 开始录制 / `q` 换个随机起点 / `x` 退出 |
| `RECORD` | **模式 B：主臂接管**，你做插入 | `d` 结束本轮 / `q` **按错了，丢弃本轮** / `x` 退出 |
| `RETURN` | 仍模式 B，把从臂带回起点附近（顺势拔出） | `c` 结束回程 / `q` 本轮标丢弃 |

→ 然后新一轮回到 `PRECISE`。**录制不做成功判断**，判断留给离线标定。

### 标定与构建

- `label_demos.py`：`DISPLAY=:0` 启动，逐帧 + 放大镜，`s` 标成功帧 / `f` 标失败
- 成功帧 `k` ⇒ 稀疏奖励落在 transition **`k-1`**，并截断到那里
- **全失败也上传**：`build_demos.py --all-failed`（reward 全 0，只作行为先验）

## 5. 关键设计决策（为什么是这样）

| 决策 | 原因 |
|---|---|
| 动作 **4 维**（pan/lift/elbow/wflex），`wrist_roll`+`gripper` 冻结 | 管子轴对称、夹爪固定；冻结维**指令=实测值**，零回复力、永不跳变 |
| `setup_mode = single-arm-fixed-gripper` | 动作里没有夹爪维，用 hybrid 模式会把最后一维当成离散夹爪头 |
| 起始随机化**只转 shoulder_pan**（±1cm 水平弧），不做 IK | IK 有 1 维零空间（转 pan + 手臂反绕到同一末端），解会跑到完全不同的姿态分支 → 真机上"起点非常高" |
| 录制**必须**走 `TrainConfig().get_environment()` | 裸 `SO101Env` 的观测是**嵌套**的，训练要扁平形态；首批 52 段因此全部作废 |
| 录制时把**干预死区设为 0** | 默认死区 0.05rad≈2.9° 比 10Hz 单步位移还大 → 81% 的步动作被记成 0 而手臂其实在动 |
| RECORD 开始时**清零步数预算** | PRECISE 的对齐会耗掉 `max_episode_steps`，否则 RECORD 第一步就 done → 1 步空段 |
| 腕部相机 **640×360** | usb_cam 行距补齐 bug（见 §6）；1920=15×128 必然对齐 |
| learner 在云端、actor 在终端 | 策略只在云端；终端算力可以很弱 |

## 6. 踩过的坑（按"最隐蔽"排序，都已在代码里修掉并写注释）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 腕部画面全是斜条纹+彩虹伪彩 | usb_cam 0.8.1 的 `mjpeg2rgb` 按对齐补齐行距（424×3=1272→**1280**），`Image.step` 却声明 1272 | 腕部改 **640×360**；`check_stride.py` 可复检 |
| 2 | 云端 jax **认得到 GPU 但一算就段错误**，无任何报错 | nvidia CUDA 轮子 12.9 世代配 jax 0.4.35（12.6 世代是同期） | 钉 nvidia-* 到 12.6；`jaxlib==jax` 同版本 |
| 3 | jax 根本 import 不了（循环导入假象） | `nvidia/cuda_nvcc` 是**命名空间包**（无 `__init__.py`），jax 0.4.35 对其取 `__file__` | 补一个空 `__init__.py` |
| 4 | 81% 的步动作是 0，而手臂在动 | 干预死区 0.05rad 比单步位移还大，而 mode B 下发不受死区影响 | 录制时 `set_intervene_deadband(0.0)` |
| 5 | 训练侧用不了录制的数据 | 裸 env 的观测是嵌套 `{state:{...},images:{...}}` | 录制走 wrapper 后的 env；`to_canonical_obs()` 可无损转换旧数据 |
| 6 | 14/52 段只有 1 步 | PRECISE 对齐耗掉 120 步 > `max_episode_steps=100` | RECORD 开始清零 `_step_count` + 退段守卫（<5 步自动丢弃） |
| 7 | 起点有时"非常高" | 三维框+IK 的零空间 | 只转 pan 的水平弧随机化 |
| 8 | 主臂使能瞬间跳起来又弹回 | `enable_torque()` 不写 `Goal_Position` | 使能前用 `Present_Position` 同步**仅力矩关闭**的电机 |
| 9 | 从臂缓慢下垂、起点歪 8.75° | P-only 位置环有稳态静差 | 归位时把收敛指令存档 `so101_home_cmd.json`，`reset()` 复用 |
| 10 | 从臂位移与录下来的 action 对不上 | 模式 B 用主臂**绝对角**会抹掉随机化 | 改**差分映射**（接管瞬间记锚点） |
| 11 | agentlace 装不上 | **不在 PyPI**，且 `serl_launcher/setup.py` 里写死了它的 git 依赖 | 从 GitHub SSH 克隆 + `pip install --no-deps serl_launcher` |
| 12 | 云端 git 克隆失败 | 云主机配了 clash 代理（127.0.0.1:7890，未必在跑）+ gh-proxy 重写 | 用 SSH 形式克隆 |
| 13 | ssh 静默去连 22 端口 | **ssh 用小写 `-p`，scp 用大写 `-P`** | 分开传参 |
| 14 | 远端脚本"启动了但什么都没发生" | `pkill -f '[t]rain_rlpd.py'` 与 nohup 写在**同一条** SSH 里，命令行文本含 `train_rlpd.py` → pkill 杀掉远端 shell 自己 | 拆成两条 SSH |
| 15 | 本地 ssh 永不返回（卡 8 分钟） | `cd X && nohup ... &` 的子 shell 持有 ssh stdout 管道 | `cd` 单独一行 + `setsid` + `</dev/null` |

## 10. 已知限制 / 待观察

- **所有验证都在 `dummy_test`（玩具环境）上**。真机的 `so101` 实验配置在云端会因缺
  `rclpy` 加载失败（正常，learner 不需要它），真机训练时要确认 actor 侧用的是 `so101`。
- 相机仍有 **~0.5% 残帧**（缓冲区只填了一部分，上面一块整行全 0）。已能自动标注，
  暂未自动剔除。
- 腕部相机改成 640×360 后出现 **~13% 重复帧**（同一帧被发布两次）。怀疑 USB 带宽，
  可把 `framerate` 从 30 降到 20 验证。
- learner 默认只跑 200 步就退出（`--max_steps`），长时间训练要调大。
- `QueuedDataStore(50000)` 在 actor 侧没有硬上限，云端 learner 若停摆可能吃内存。
