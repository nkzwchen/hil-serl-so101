## 稳定观测帧率统计（2026-10-08）

## 2026-10-08 发布调度与接收停顿排查

### 已定位并修复：双定时器覆盖有效帧

原版取帧和发布各用一个定时器，都在默认互斥回调组、单线程执行器中运行。
取帧会等待 V4L2 数据，发布回调不能同时执行；两者节拍不一致时，多个有效源帧
可能在一次发布前到达，单帧缓存会覆盖前面的未发布帧。额外单调时钟节拍还会跳过
提前触发的发布检查。仅把 publish_rate 从 10 改为 30，不会消除这条双定时器路径。

新增只读启动参数 `publish_on_capture`：默认在 `publish_rate >= framerate` 时为 true，
30/30 配置采用“成功取帧、更新有效缓存、立即检查并发布”，不创建独立发布定时器，
也不额外按发布截止时刻筛掉有效新帧。节拍由采集定时器和相机供帧控制，
这不是独立单调时钟严格限速器，实际速率仍须测量。
低频发布（例如 30/10）默认 false，继续使用独立定时器与单调时钟节拍。
可显式设置 false 复现原版；显式 true 要求 publish_rate 不小于采集目标。
坏帧不更新缓存、源时间戳检查、100ms 采集年龄保护和原 QoS 均保留。

统计增加 `publish_on_capture`、`capture_callback_last_ms`、`capture_callback_max_ms`、
`publish_gap_max_ms`，区分取帧回调耗时、发布调用耗时和发布间隔。
最大值覆盖节点启动至退出；起止快照差值覆盖采样附近窗口，不能混为同一统计窗口。
