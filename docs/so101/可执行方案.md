# SO101 ROS2 接入 OpenPI 远程推理可执行方案

## 1. 目标

把 `so101_ros2-main` 作为 SO101 机械臂的 ROS2 硬件通信与控制底座，新增一个 OpenPI 远程推理 policy adapter，使系统形成下面这条链路：

```text
SO101 机械臂 + 相机
  -> so101_ros2-main ROS2 节点
  -> policy_runner 同步图像和关节状态
  -> OpenPI WebSocket client
  -> openpi/scripts/serve_policy.py 远程推理服务
  -> action chunk
  -> policy_runner 发布 JointState
  -> 现有 teleop/controller/follower bridge 控制 SO101
```

核心原则：**不重写底层 SO101 串口通信，不改 OpenPI 模型推理服务，只在 `so101_ros2_bridge/policy` 下新增 OpenPI 远程 policy。**

## 2. 当前软件能力判断

`so101_ros2-main` 已经足够完成以下硬件侧功能：

- 连接 SO101 follower/leader，底层使用 LeRobot 的 `SO101Follower` / `SO101Leader`。
- 发布 follower 当前关节状态。
- 接收控制命令并调用 `robot.send_action()` 控制真实机械臂。
- 启动 USB camera / RealSense camera。
- 通过 `policy_runner_ros2_node` 同步图像和关节状态，并周期性调用 policy。
- 将 policy 输出动作发布为 `JointState`，复用现有 teleop/control 链路控制 follower。

当前不足：

- 现有 policy 只注册了 `smolvla`。
- `smolvla.py` 是本地 LeRobot 模型推理，不是 OpenPI WebSocket 远程推理。
- 需要新增 `openpi_remote.py`，把 ROS2 observation 转成 OpenPI 需要的 observation dict。

## 3. 推荐实施路线

### 阶段 A：先确认 OpenPI SO101 服务端能跑

在 OpenPI 环境中启动远程 policy server：

```bash
cd /root/rivermind-data/openpi

uv run scripts/serve_policy.py policy:checkpoint \
  --policy.config=pi05_so101 \
  --policy.dir=/root/rivermind-data/openpi/checkpoints/pi05_so101 \
  --port=8000
```

健康检查：

```bash
curl http://127.0.0.1:8000/healthz
```

期望输出：

```text
OK
```

说明：

- `serve_policy.py` 默认 `--env` 不包含 SO101，所以这里使用 `policy:checkpoint`。
- 如果 OpenPI 服务端和 ROS2 控制端不在同一台机器，把客户端配置里的 host 改成服务端 IP。

### 阶段 B：在 ROS2/LeRobot 环境安装 OpenPI client

进入运行 `so101_ros2-main` 的 Python 环境，例如：

```bash
conda activate lerobot_ros2
cd /root/rivermind-data/openpi/packages/openpi-client
pip install -e .
```

验证：

```bash
python -c "from openpi_client.websocket_client_policy import WebsocketClientPolicy; print('ok')"
```

## 4. 需要修改的文件

### 4.1 新增 policy adapter

新增文件：

```text
so101_ros2/so101_ros2_bridge/so101_ros2_bridge/policy/openpi_remote.py
```

职责：

- 连接 OpenPI WebSocket server。
- 把 ROS2 同步后的消息转换成 OpenPI observation。
- 调用 `client.infer(observation)`。
- 取 `result["actions"]`，写入现有 `ActionBuffer`。
- `get_action()` 每次返回 action chunk 中的一步。

建议实现结构：

```python
from __future__ import annotations

import math
from typing import Any, List, Mapping, Optional

import numpy as np
from openpi_client.websocket_client_policy import WebsocketClientPolicy
from rclpy.logging import LoggingSeverity
from rclpy.node import Node

from ..utils.buffer import ActionBuffer
from ..utils.conversion import ros_image_to_hwc_uint8, ros_jointstate_to_vec
from ..utils.filtering import LowPassFilter
from .base import BasePolicy, PolicyConfig
from .registry import register_policy


@register_policy("openpi_remote")
class OpenPIRemote(BasePolicy):
    def __init__(self, cfg: PolicyConfig, node: Node) -> None:
        super().__init__(cfg, node)
        self.node = node

        extra = cfg.extra or {}
        server_cfg = extra.get("server", {})
        obs_cfg = extra.get("observation", {})
        lpf_cfg = extra.get("lpf_filtering", {})

        host = server_cfg.get("host", "127.0.0.1")
        port = int(server_cfg.get("port", 8000))

        self._base_image_key = obs_cfg.get("base_image_key", "observation.images.camera1")
        self._wrist_image_key = obs_cfg.get("wrist_image_key", "observation.images.camera2")
        self._state_key = obs_cfg.get("state_key", "observation.state")
        self._task = cfg.task

        robot_props = cfg.robot_properties
        self._state_joint_names: List[str] = robot_props.get(
            "state_joint_names",
            robot_props.get("joint_names"),
        )

        self._client = WebsocketClientPolicy(host=host, port=port)
        self.node.get_logger().info(
            f"[OpenPIRemote] Connected to OpenPI server {host}:{port}, "
            f"metadata={self._client.get_server_metadata()}"
        )

        lpf = None
        if lpf_cfg.get("enable", False):
            lpf = LowPassFilter(alpha=float(lpf_cfg.get("alpha", 0.1)))
        self._action_buffer = ActionBuffer(lpf=lpf)

    def make_observation(self, ros_obs: Mapping[str, Any]) -> dict:
        base_img = ros_image_to_hwc_uint8(ros_obs[self._base_image_key])
        wrist_img = ros_image_to_hwc_uint8(ros_obs[self._wrist_image_key])
        state, _ = ros_jointstate_to_vec(
            ros_obs[self._state_key],
            joint_order=self._state_joint_names,
            use_lerobot_ranges_norms=False,
        )

        return {
            "observation/image": base_img,
            "observation/wrist_image": wrist_img,
            "observation/state": state.astype(np.float32),
            "prompt": self._task,
        }

    def predict_action_chunk(
        self,
        observation: dict,
        time_per_action: float,
        inference_delay: float,
    ) -> None:
        result = self._client.infer(observation)
        actions = np.asarray(result["actions"], dtype=np.float32)

        if actions.ndim != 2:
            self.node.get_logger().error(
                f"[OpenPIRemote] Expected actions shape [T, D], got {actions.shape}"
            )
            return

        actions_list = actions.tolist()
        if not actions_list:
            self.node.get_logger().warn("[OpenPIRemote] Empty action chunk returned.")
            return

        if inference_delay > 0.0 and time_per_action > 0.0:
            start_index = math.ceil(inference_delay / time_per_action)
        else:
            start_index = 0

        self._action_buffer.set(actions_list, start_index=start_index)
        self.node.get_logger().log(
            f"[OpenPIRemote] Received action chunk shape={actions.shape}, "
            f"start_index={start_index}",
            severity=LoggingSeverity.INFO,
            throttle_duration_sec=5.0,
        )

    def get_action(self) -> Optional[List[float]]:
        return self._action_buffer.get()

    def reset(self, context: Optional[Mapping[str, Any]] = None) -> None:
        self._action_buffer.reset()
```

### 4.4 修改 policy 参数

修改：

```text
so101_ros2/so101_ros2_bridge/config/so101_policy_params.yaml
```

建议内容：

```yaml
/**:
  ros__parameters:
    inference_rate: 2.5
    inference_delay: 0.4
    publish_rate: 25.0
    sync.queue_size: 20
    sync.slop: 0.1

    policy_name: "openpi_remote"
    device: "cpu"
    checkpoint_path: "/tmp/openpi_remote_dummy"
    task: "pick up the orange"
```

说明：

- `checkpoint_path` 对远程 OpenPI 没有实际用途。
- 目前 `PolicyConfig.create()` 强制要求绝对路径，所以先给一个绝对 dummy 路径。
- 更干净的做法见下一节。

### 4.5 建议优化 PolicyConfig

当前文件：

```text
so101_ros2-main/so101_ros2_bridge/so101_ros2_bridge/policy/base.py
```

当前逻辑要求所有 policy 都必须提供绝对 `checkpoint_path`。对 `openpi_remote` 来说，checkpoint 在 OpenPI server 端，本地不需要。

建议改成：

```python
remote_policies = {"openpi_remote"}

if policy_name not in remote_policies:
    if checkpoint_path:
        if not checkpoint_path.is_absolute():
            raise ValueError(f"Checkpoint path must be absolute: {checkpoint_path}")
    else:
        raise ValueError("Checkpoint path must be provided and non-empty.")
```

这样 `openpi_remote` 就不需要 dummy checkpoint。

## 5. IO 映射确认

当前 `io.yaml` 默认：

```yaml
observations:
  observation.images.camera1:
    topic: "/follower/cam_front/image_raw"
    msg_type: "sensor_msgs/msg/Image"

  observation.images.camera2:
    topic: "/static_camera/cam_side/color/image_raw"
    msg_type: "sensor_msgs/msg/Image"

  observation.state:
    topic: "/follower/joint_states"
    msg_type: "sensor_msgs/msg/JointState"

action:
  topic: "/leader/joint_states"
  msg_type: "sensor_msgs/msg/JointState"
```

需要确认：

- `observation.images.camera1` 是否对应训练时的 `observation/image`，通常是主视角。
- `observation.images.camera2` 是否对应训练时的 `observation/wrist_image`，如果训练时是腕部相机，这里应改成腕部相机 topic。
- `observation.state` 的 joint 顺序是否和训练数据一致。
- `action` 输出维度是否是 6，并对应：

```text
shoulder_pan
shoulder_lift
elbow_flex
wrist_flex
wrist_roll
gripper
```

如果 JointState 名称顺序不稳定，建议在 `io.yaml` 中显式写 names：

```yaml
observation.state:
  topic: "/follower/joint_states"
  msg_type: "sensor_msgs/msg/JointState"
  names:
    - "shoulder_pan"
    - "shoulder_lift"
    - "elbow_flex"
    - "wrist_flex"
    - "wrist_roll"
    - "gripper"

action:
  topic: "/leader/joint_states"
  msg_type: "sensor_msgs/msg/JointState"
  names:
    - "shoulder_pan"
    - "shoulder_lift"
    - "elbow_flex"
    - "wrist_flex"
    - "wrist_roll"
    - "gripper"
```


### 7.3 验证动作维度

OpenPI 返回动作应为：

```text
actions.shape == (action_horizon, action_dim)
```

对当前 `pi05_so101`，预期通常是：

```text
(10, 6)
```

如果不是 6 维，先不要上真实机械臂，先检查训练配置和 `SO101Outputs`。

## 8. 时序参数建议

OpenPI SO101 配置中 `action_horizon=10`。如果：

```text
publish_rate = 25 Hz
```

那么 10 个动作约 0.4 秒执行完，因此：

```text
inference_rate ≈ 2.5 Hz
```

推荐起步参数：

```yaml
inference_rate: 2.5
publish_rate: 25.0
inference_delay: 0.4
```

如果模型推理慢，可以先降级为：

```yaml
inference_rate: 1.0
publish_rate: 10.0
inference_delay: 0.5
```

## 9. 关键风险点

### 9.1 state/action 单位必须一致

`so101_ros2-main` ROS2 侧的 `JointState.position` 是弧度。OpenPI 训练数据如果来自同一套 ROS bag -> LeRobot 转换流程，通常可以匹配。

如果你的 OpenPI checkpoint 是用 LeRobot 原生 SO101 数据训练的，可能存在：

- degree
- normalized range
- radians

三种语义不一致的问题。

一旦单位错了，模型不一定报错，但机械臂动作会明显异常。

### 9.2 相机语义必须一致

OpenPI 的 SO101 transform 期望：

```python
"observation/image"
"observation/wrist_image"
```

不要只看 topic 名字，要确认：

- 主视角是不是训练时主视角。
- 腕部视角是不是训练时腕部视角。
- 图像方向是否需要旋转。
- 图像是否 RGB。

### 9.3 先仿真/架空验证，再接真实机械臂

上线真实机械臂前，建议先：

- 只启动 policy runner，不激活 follower 控制。
- echo `/leader/joint_states` 看动作是否平滑。
- 检查动作范围是否合理。
- 手放急停位置，再激活真实控制。

## 10. 最小验收标准

完成后应满足：

- `policy_name: openpi_remote` 能成功 configure。
- configure 时能连接 OpenPI WebSocket server。
- activate 后能持续收到 camera + joint state 同步观测。
- OpenPI server 日志能看到推理请求。
- `/leader/joint_states` 能持续发布 6 维动作。
- follower 能按 policy 输出动作执行。
