## 1. 测试目的与范围

**目的**：在**不接硬件**的前提下，验证「云端训练+推理 / 终端设备交互」这条跨机链路本身是通的。

**范围**

| SSH 隧道 + agentlace 双端口连通 | 相机图像质量（已在另一批测试单独验） |
| learner 启动、加载 demo、出 ckpt | 真实录制数据的训练效果 |
| actor 连接、握手、数据上行 | reward classifier |
| 双边速率与 GPU 占用 | wandb 云端日志（`--debug` 关闭） |
| `build_demos` → 上传链路 | — |

## 6. 测试脚本自身的问题（已修，记录以免重犯）

这轮测试里有 5 个失败**全部是测试脚本的 bug**，不是被测系统的问题。
它们同时也是"跨机自动化"的典型陷阱，值得记下来：

| 现象 | 根因 | 已修 |
|---|---|---|
| learner 启动后日志文件是空的 | `pkill -f '[t]rain_rlpd.py'` 与 nohup 写在**同一条** SSH 命令里；该命令的命令行文本含 `train_rlpd.py` → pkill 把远端 shell 自己杀了 | 拆成两条 SSH 调用 |
| 本地 ssh 卡住 8 分钟不返回 | `cd X && nohup ... &` 会把整个 `cd && nohup` 组放进后台**子 shell**，该子 shell 持有 ssh 的 stdout 管道 | `cd` 单独一行 + `setsid` + `< /dev/null` |
| 隧道 `bind: Address already in use` | 上次运行残留的 `ssh -f -N` 进程没清干净 | `cloud_link.sh start` 先清残留 |
| 判定"learner 收到数据"失败 | tqdm 会输出**两种**形态（完成形式 `24it` / 进行中形式 `\| 4/10`），而检查只认了一种 | 两种都解析，取较大者（已用存档日志回归：`24` ✅） |
| `ERROR: no recording files found` | 用了相对路径，而脚本工作目录不是项目根 | 改绝对路径 |

另有两次"命令把自己杀了"：`pkill -f <模式>` 中**模式字符串本身出现在当前命令行里**
→ 匹配到自己。用方括号技巧（`[t]rain`）只在"模式是命令行里唯一出现处"时有效。

## 7. 结论

1. **「云端训练+推理 / 终端设备交互」的跨机架构成立且可用**——
   云端 learner 在 L40S 上以 ~40 it/s 训练、显存 34.5 GB，终端 actor 经 SSH 隧道
   2 秒完成握手并持续上行数据。
2. **测试可复现**：`bash so101_tools/offline_e2e_test.sh` 一条命令跑完 9 项，
   两端日志落盘留证（路径见 §5）。
3. **云端环境可一键复现**（`setup_cloud_env.sh` + `check_cloud_env.py`），
   自检覆盖版本、GPU 计算、训练栈构建三项。
4. **数据流水线闭环打通**：录制 → 标定 → `build_demos` → 上传 → 作为 `--demo_path` 加载。
5. **剩下要做的只有"接上真机跑一遍"**：
   所有验证都在玩具环境上完成，`SO101Env` 的真机控制回路（关节下发、力矩状态机、
   相机采集）此前已单独验过，但没有和这套云端链路合并跑过。

## 8. 遗留风险

| 风险 | 影响 | 建议 |
|---|---|---|
| learner 默认只跑 200 步就退出 | 长训练会提前结束 | 调大 `--max_steps` 并确认 checkpoint 落盘 |
| 真机训练时云端会因缺 `rclpy` 跳过 `so101` 配置 | 只是告警（learner 不需要 env） | 确认 actor 侧用 `--exp_name so101` |
| 相机 ~0.5% 残帧、腕部 ~13% 重复帧 | 少量 obs 失真 | 降 `framerate` 到 20 验证 |
| `QueuedDataStore(50000)` 无硬上限 | learner 停摆时 actor 侧吃内存 | 需要时加硬上限 |
| 云端 `/` 仅 17 GB | 误装大包会写满 | 一切装到 `/root/gpufree-data` |
